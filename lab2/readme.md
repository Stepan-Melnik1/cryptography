# Cryptography Lab 2 — End-to-End Encryption

## Описание проекта

Данный проект разработан в рамках лабораторной работы №2 по криптографии «Сквозное шифрование».

Программа реализована на языке **C++** и демонстрирует обмен секретными ключами с использованием алгоритмов Диффи — Хеллмана (DH) и Диффи — Хеллмана на эллиптических кривых (ECDH), а также шифрование и дешифрование сообщений с помощью блочного алгоритма RC2.

## Используемые технологии

- Язык программирования: C++
- Стандартная библиотека C++
- Компилятор: G++
- Алгоритм обмена ключами: Diffie–Hellman (DH)
- Эллиптический обмен ключами: Elliptic Curve Diffie–Hellman (ECDH)
- Алгоритм шифрования: RC2
- Спецификация RC2: RFC 2268

## Реализованные алгоритмы

### 1. Diffie–Hellman (DH)

Реализован классический алгоритм обмена ключами Диффи — Хеллмана.

Основные функции:

- `randnumgen()` — генерация случайных чисел.
- `primenumtest()` — проверка числа на простоту.
- `exponentiation()` — быстрое возведение в степень по модулю.
- `isPrimitiveRoot()` — проверка первообразного корня по модулю.
- `DH_keygen()` — генерация параметров, закрытых и открытых ключей, а также общего секретного ключа.

Алиса и Боб генерируют собственные закрытые ключи и обмениваются открытыми ключами. После этого обе стороны независимо вычисляют одинаковый общий секрет.

### 2. Elliptic Curve Diffie–Hellman (ECDH)

Реализован обмен ключами на основе математических операций с точками эллиптической кривой.

Основные функции:

- `modInverse()` — нахождение обратного элемента по модулю.
- `positiveMod()` — получение положительного остатка от деления.
- `isOnCurve()` — проверка принадлежности точки эллиптической кривой.
- `pointAdd()` — сложение двух точек.
- `pointMultiply()` — умножение точки на скаляр.
- `ECDH_keygen()` — генерация закрытых и открытых ключей и вычисление общего секретного значения.

Используемое уравнение эллиптической кривой:

```text
y² = x³ + Ax + B (mod p)
```

Программа позволяет пользователю самостоятельно вводить параметры кривой:

- `p` — простой модуль;
- `curveA` — первый коэффициент кривой;
- `curveB` — второй коэффициент кривой;
- `Gx` — координата X точки-генератора;
- `Gy` — координата Y точки-генератора;
- `n` — порядок точки-генератора.

Для проверки ECDH реализован пример из лабораторной работы:

```text
p = 17
curveA = 2
curveB = 2
G = (5, 1)
n = 19
```

При закрытых ключах Алисы `6` и Боба `15` получаются следующие результаты:

```text
Alice public key: (16, 13)
Bob public key:   (3, 16)
Shared key:       (9, 1)
```

Обе стороны получают одинаковую секретную точку.

Для передачи результата в RC2 используется учебное преобразование координат общей точки в число:

```text
key = x * p + y
```

### 3. RC2 Encryption Algorithm

Реализовано блочное шифрование RC2 и обратное дешифрование.

Размер блока составляет 64 бита (8 байт). Для расширения исходного ключа используется таблица перестановок PITABLE из RFC 2268.

Реализованы следующие функции:

- `ROL()` — циклический сдвиг битов влево.
- `ROR()` — циклический сдвиг битов вправо.
- `mixing()` — операция перемешивания регистров.
- `mashing()` — операция наложения значений расширенного ключа.
- `padding()` — дополнение сообщения до размера блока.
- `keyexp()` — расширение исходного ключа до 64 слов по 16 бит.
- `RC2_encrypt()` — шифрование сообщения.
- `RC2_decrypt()` — дешифрование сообщения.

Процесс шифрования включает:

1. Расширение исходного ключа.
2. Дополнение сообщения до размера блока.
3. Разделение сообщения на блоки по 8 байт.
4. Загрузку данных в четыре 16-битных регистра: R0, R1, R2 и R3.
5. Выполнение 16 раундов Mixing.
6. Выполнение двух раундов Mashing — после пятого и одиннадцатого раундов Mixing.
7. Формирование зашифрованного сообщения.

Дешифрование выполняет обратные операции в обратном порядке.

## Проверка корректности

Для проверки реализации добавлены автоматические тесты.

### RC2

Реализованы пять проверок:

1. Первый официальный тестовый вектор RFC 2268: нулевой ключ длиной 8 байт и эффективная длина 63 бита.
2. Второй официальный тестовый вектор RFC 2268: ключ `88` и эффективная длина 64 бита.
3. Шифрование и дешифрование сообщения, превышающего размер одного блока.
4. Проверка обработки пустого сообщения.
5. Проверка сообщения с нулевыми байтами в конце.

### ECDH

Проверяется пример эллиптической кривой из лабораторной работы.

Проверяются открытые ключи Алисы и Боба, совпадение общих секретных точек и порядок точки-генератора.

## Компиляция

Для компиляции проекта в Linux необходимо выполнить команду:

```bash
g++ main.cpp dh.cpp rc2.cpp -o crypto
```

После успешной компиляции будет создан исполняемый файл `crypto`.

## Запуск программы

Программа поддерживает четыре режима работы.

### 1. Шифрование с использованием классического DH

```bash
./crypto -Edhrc2 IWILLBEHEREONMONDAY
```

Программа автоматически генерирует параметры DH, получает общий секретный ключ и шифрует сообщение.

Пример формата результата:

```text
enc: [зашифрованное сообщение в HEX]
key: [общий секретный ключ]
```

Полученные HEX-строку и ключ необходимо сохранить для последующего дешифрования.

### 2. Дешифрование с использованием классического DH

```bash
./crypto -Ddhrc2
```

Программа запрашивает зашифрованное сообщение в HEX-формате и ранее полученный общий секретный ключ.

Результат:

```text
dec: IWILLBEHEREONMONDAY
```

### 3. Шифрование с использованием ECDH

```bash
./crypto -Eecdhrc2 HELLO
```

Программа запрашивает параметры эллиптической кривой:

```text
Enter p, curveA, curveB, Gx, Gy, n:
```

Пример ввода:

```text
17 2 2 5 1 19
```

После этого генерируются закрытые ключи Алисы и Боба, вычисляются открытые ключи и общий секрет. Полученный секрет преобразуется в ключ RC2, после чего выполняется шифрование сообщения.

Пример формата результата:

```text
enc: [зашифрованное сообщение в HEX]
key: [общий секрет]
```

### 4. Дешифрование с использованием ECDH

```bash
./crypto -Decdhrc2
```

Программа запрашивает HEX-сообщение и общий секрет, полученный при шифровании.

Результат:

```text
dec: HELLO
```

## Ограничения реализации

Данная программа предназначена для изучения криптографических алгоритмов и демонстрации принципов обмена ключами и симметричного шифрования.

- Для классического DH используются небольшие учебные параметры.
- Для ECDH используется учебная эллиптическая кривая с небольшим простым модулем.
- Преобразование общей точки ECDH в числовой ключ RC2 является упрощённым учебным решением.
- Для дополнения сообщений используется заполнение нулевыми байтами.
- RC2 является устаревшим алгоритмом и не рекомендуется для защиты реальной конфиденциальной информации.

Программа не предназначена для использования в качестве промышленной системы защиты данных.

## Заключение

В результате выполнения лабораторной работы реализованы два способа обмена секретными ключами — классический DH и ECDH, а также алгоритм симметричного блочного шифрования RC2.

Реализованы вспомогательные функции, обеспечивающие выполнение криптографических операций, разделение программы на модули и проверка корректности работы с использованием тестовых векторов RFC 2268 и примера ECDH из методических материалов.
